# 플러그인 저장소와 플러그인 간 데이터 공유

PocketRisu v1.11.0부터 플러그인 데이터(`pluginCustomStorage`)가 저장되는 위치와 플러그인이 다른 플러그인의 데이터를 읽는 방법을 설명합니다. 플러그인 제작자와, "다른 플러그인 데이터 전체 제공" 옵션을 켤지 고민하는 사용자를 위한 문서입니다.

- [1. 무엇이 달라졌나](#1-무엇이-달라졌나) : 플러그인 데이터가 서버 저장소로 이동
- [2. 사용자 안내](#2-사용자-안내) : 플러그인이 다른 플러그인 데이터를 못 읽을 때
- [3. 제작자 안내](#3-제작자-안내) : 권장 API와 호환 방법
- [4. 비용과 주의점](#4-비용과-주의점) : 전체 제공 옵션이 무거운 이유
- [5. 백업과 호환성](#5-백업과-호환성)


## 1. 무엇이 달라졌나

원본 RisuAI에서는 모든 플러그인의 데이터가 `database.bin` 안의 `pluginCustomStorage` 객체 하나에 들어 있었습니다. 장기기억 플러그인처럼 데이터가 수백 MB로 쌓이면 이 객체 때문에 브라우저가 멈추거나 저장에 실패했습니다.

PocketRisu v1.11.0부터는 플러그인 값이 **서버 데이터베이스에 키별로** 저장되고, 브라우저는 필요한 키만 읽습니다. 그 결과:

- `database.bin`과 앱의 메인 메모리 DB에서 플러그인 데이터가 빠져 대용량 플러그인이 있어도 앱이 정상 동작합니다. (V2 preload와 아래의 전체 제공 옵션은 값을 메모리에 올립니다. 4절 참고.)
- V2 / V2.1 플러그인은 동기 API라 첫 V2 플러그인이 실행되기 직전에 모든 키를 미리 읽어 둡니다. 예전과 같은 동작이며 플러그인 로드 때마다 한 번 전체를 받습니다.
- V3 플러그인이 `getDatabase()`로 받는 스냅샷의 `pluginCustomStorage`는 **기본적으로 비어 있습니다.** 값을 통째로 복사해 넘기는 비용이 크기 때문입니다.

이 마지막 항목이 원본 RisuAI와 다른 부분입니다. 다른 플러그인의 데이터를 `getDatabase().pluginCustomStorage[...]`로 읽던 V3 플러그인은 PocketRisu에서 빈 값을 받습니다.


## 2. 사용자 안내

어떤 플러그인이 다른 플러그인의 데이터를 읽어야 동작하는데(예: 여러 기억 플러그인의 내용을 모아 쓰는 통합 플러그인) PocketRisu에서 그 부분이 동작하지 않는다면:

1. 먼저 플러그인이 PocketRisu 대응 버전을 제공하는지 확인합니다. 제작자가 아래 3절의 방법으로 대응했다면 별도 설정 없이 동작합니다.
2. 대응 버전이 없다면 **설정 > 플러그인**에서 해당 플러그인을 눌러 세부 설정을 열고 **"다른 플러그인 데이터 전체 제공 (원본 RisuAI 호환)"** 을 켭니다. 그 플러그인은 원본 RisuAI와 같은 모양의 데이터를 받습니다.

이 옵션은 **정말 필요한 플러그인에만** 켜세요. 켠 플러그인이 DB를 읽을 때마다 플러그인 저장소 전체가 복사됩니다(4절 참고). 옵션 설명에 현재 저장소 용량이 표시됩니다.

옵션을 켜도 되는지 판단이 어려우면 브라우저 개발자 도구(F12) 콘솔을 확인합니다. 데이터를 못 읽은 플러그인은 `[RisuAI Plugin: 이름] getDatabase() returns an empty pluginCustomStorage on PocketRisu` 경고를 남깁니다.


## 3. 제작자 안내

V3 플러그인에서 다른 플러그인(또는 자기 자신)의 저장값을 읽는 방법은 두 가지입니다.

### 방법 A. `pluginStorage.getItem(key)` (권장)

```js
const value = await risuai.pluginStorage.getItem('other-plugin-key')
```

필요한 키 하나만 서버에서 읽습니다. 가장 가볍고, 저장소가 아무리 커도 비용이 일정합니다. 키 공간은 플러그인 구분 없이 하나이므로 다른 플러그인이 쓴 키 이름을 그대로 넘기면 됩니다.

### 방법 B. 사용자 옵션

코드를 고칠 수 없는 경우 사용자가 2절의 옵션을 켜면 `getDatabase()`가 전체 값을 돌려줍니다. 제작자 입장에서는 사용자에게 옵션을 켜도록 안내해야 하므로 A를 권장합니다.

`getDatabase(['pluginCustomStorage'])`처럼 `includeOnly`에 키를 명시해도 값이 채워지지 **않습니다.** 값을 쓰지 않으면서 이 키를 습관적으로 명시하는 플러그인(플러그인 매니저 등)이 흔해서, 명시를 "저장소 전체가 필요하다"는 요청으로 볼 수 없기 때문입니다. 전체 제공은 사용자 옵션으로만 켜집니다.

### 쓰기

`setDatabase({ pluginCustomStorage: {...} })`는 넘긴 키를 **병합**합니다. 빠진 키를 삭제하지 않으므로, 일부만 읽어 일부만 되써도 다른 플러그인의 데이터가 지워지지 않습니다. 삭제는 `pluginStorage.removeItem(key)`를 사용합니다.


## 4. 비용과 주의점

플러그인 저장소는 플러그인별로 나뉘어 있지 않습니다. 따라서 "전체 제공"은 특정 플러그인의 데이터만 잘라 주는 것이 아니라 **설치된 모든 플러그인의 저장값 전체**를 서버에서 받아 플러그인 실행 환경으로 복사하는 동작입니다.

- 장기기억 플러그인이 있으면 저장소가 수백 MB에 이를 수 있습니다.
- V3 플러그인은 격리된 환경에서 실행되므로 `getDatabase()` 결과는 호출할 때마다 복사됩니다. 메시지마다 `getDatabase()`를 부르는 플러그인에 이 옵션을 켜면 매 메시지마다 수백 MB를 복사하게 됩니다.
- 옵션 설명에 표시되는 저장소 용량이 100 MB를 넘으면 경고가 함께 표시됩니다.

앱이 느려지거나 멈추면 해당 플러그인의 옵션을 끄고, 제작자에게 방법 A 대응을 요청하세요.


## 5. 백업과 호환성

- 전체 `.bin` 백업 파일은 내보낼 때 플러그인 데이터를 다시 합쳐 담으므로 원본 RisuAI와 구버전 PocketRisu에서 그대로 열립니다. 설정만 내보내는 백업에는 플러그인 데이터가 비어 있습니다.
- "다른 플러그인 데이터 전체 제공" 설정은 플러그인 항목에 함께 저장되며, 원본 RisuAI로 옮기면 무시됩니다.
- PocketRisu v1.10.x 이하로 되돌리면 구버전은 서버 저장소의 플러그인 데이터를 읽지 못합니다. 되돌리기 전에 설정 > DB 백업 목록에서 업데이트 직전 스냅샷을 복원하세요.


## 6. 브라우저의 로컬 플러그인 저장소

`risuai.getLocalPluginStorage()`는 위의 `risuai.pluginStorage`와 별개입니다. 원본 RisuAI와 같은 localForage DB `plugin`, 스토어 `plugin`, 키 접두사 `safe_plugin_`를 사용하며, IndexedDB가 지원되는 브라우저에서는 Blob·ArrayBuffer 등을 그대로 보존합니다. 값과 작성 플러그인 정보는 접속한 브라우저의 사이트 주소(origin)에 저장됩니다.

첫 사용 시 기존 PocketRisu 서버 값을 한 번 복사합니다. 이미 브라우저에 있는 값은 덮어쓰지 않으며 서버 원본도 삭제하지 않습니다. 복사가 완료된 뒤에는 읽기·쓰기·삭제·초기화가 모두 브라우저에서 처리되고, 서버의 변경 사항은 다시 가져오지 않습니다. 복사에 실패하면 완료 표시를 남기지 않고 다음 호출에서 재시도합니다.

이 값들은 기기·브라우저·사이트 주소가 달라지면 공유되지 않으며 `.bin` 백업에도 포함되지 않습니다. 저장소 API의 `clear()`는 복사 완료 표시를 유지하므로 삭제한 값이 다시 복사되지 않습니다. 브라우저의 사이트 데이터를 전부 지우면 완료 표시도 지워져 다음 사용은 다시 첫 사용으로 취급됩니다. 이전 JSON 저장 과정에서 잃어버린 바이너리 내용은 복사로 복구할 수 없습니다.

서버 값의 안전한 최초 복사는 IndexedDB 또는 Web Locks가 필요합니다. 둘 다 없는 환경에서 아직 복사할 값이 남아 있다면 기존 데이터를 변경하지 않고 오류를 반환합니다. 브라우저에만 저장한 `saveAsset()` 경로는 서버의 에셋 정리에서 참조로 확인되지 않으므로, 로컬 음성·이미지 보관에는 Blob 자체를 저장하세요.
